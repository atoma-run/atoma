## Change and adversarial review

A focused approval still cannot erase a holistic refusal. Only an explicit
criterion disagreement beside a complete focused approval opens one additional
L1, tool-free reread. It receives the same host evidence and both labeled,
fallible judgments. A complete new whole-task verdict may correct the false
refusal; malformed, truncated, missing, duplicate or negative judgments cannot
promote it. Provider failure preserves the earlier refusal; cancellation
propagates. Original inherited-check and mechanical safeguards still apply.
Ordinary approvals, non-criterion refusals, focused failures, drafted lists,
landings and text deliveries retain their call count. This adds at most one
cheap call in the contradictory case, never another execution pass.

Adversarial cases include a correct width with an unrelated injection defect,
an incomplete reread, a reread contradicting its own approval, transport failure,
and cancellation. Existing criteria-review tests retain the missing-test-body
false positive and the out-of-checklist refusal. The browser guidance applies
to plain-text sinks, not arbitrary occurrences of `innerHTML`; intentional rich
HTML remains governed by its sanitization contract. Direct opening is required
only if promised; a documented required static server is valid. No vocabulary
detector, supervisor replay of README commands, or blanket module ban is added.

Mocked review tests prove control flow and guidance delivery, not model accuracy.
Browser tests prove the counterexamples through actual Chrome behavior. A later
live campaign is needed to measure whether models follow the new guidance.
