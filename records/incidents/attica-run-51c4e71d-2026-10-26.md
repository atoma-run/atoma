execution on the owner's Mac, Compute 0.4.128, models own:openai luna/terra/

## Verified findings

1. **Blocking.** The remediation pass was a read-only verification; its root
   plan declared `delivery: 'text'`. `persistDeclaredArtifactManifest` writes
   the LAST recorded root plan, so `declared-artifacts.json` said text, the
   Compute export built a text manifest over 249 files, and `atoma_run_review`
   reports `comparisonState: text_only`. With `delivery: 'text'` the root
   judge also skipped `reviewAcceptanceCriteria` (file deliveries only) and
   built a text reference instead. Accepting would bind the client's consent
   to a text manifest and publish nothing.
2. **About 32 minutes.** The project's own browser tests leave Chromium's
   `.atoma-runtime/xe-browser-profile/SingletonSocket` link (target under
   `/tmp`). The parent-test copy refused it (`snapshot-link`), so every suite
   of every branch and tier produced no result. The `no-result` gate rejects
   once PER TASK: five rejections (Protoplast's CarbonDioxide, Meristem's
   Companion and Protoplast, both Ammonias), two escalations, both branches
   rebuilt. The publication inventory had already learned to omit such
   byte-less entries on 2026-10-25; the copy had not.
3. **11.7 minutes.** The first root judge refused c4 ("no observed real-browser
   execution demonstrates the page's 404, 503-HTML and network-loss
   messages") while the browser suite had passed 25/25 at 05:57. Two causes
   in the evidence it read: the criterion-word tokenizer
   (`/[a-z][a-z0-9_-]{3,}/`) never matched `404` or `503`, so the
   `test.each([404, 503, 'network'])` cases past the suite file's head were
   not selected; and the two recorded browser receipts were rendered as
   `PARTIAL SHELL OBSERVATION` cut to their request plus the last sixty
   characters of their result, so "Tests 25 passed (25)" reached no judge
   (the "child's own probe outputs" showed an earlier 22/22 run). The
   remediation changed no file; the second judge approved on the same code.
4. **Text calls to Codex ran one at a time.** `profile-local-wait` summed to
   1,020 s over 196 text calls (max 166 s), `profile-wait` 206 s over 46 tool
   calls. The text transport leased the personal `CODEX_HOME` for the child's
   whole lifetime; a parallel branch's planner waited behind its sibling's
   validator.
5. **Plan reviews on the smallest model refused 18 of 36 plans**, 14 counted.
   Three recurring misreadings: the integration-placement rule applied to a
   sequential plan with ONE implementation subtask (Meristem → Companion,
   twice: "its Vitest suite is attached to subtask 0 rather than the final
   join"); a "bounded automatic retry" demanded in six refusals for a task
   that says the page retries and recovers by itself (the delivered code
   carries `maxAutomaticRetries = 3` because of it); and L2 validators
   refusing L1 plans for gaps in the PARENT's suite, which the L1 cannot
   change (Protoplast → Sucrose, four times: "the parent acceptance suite has
   a blocking coverage defect … before implementation runs").
6. **About 20 minutes.** Meristem refused Protoplast's phase on "the current
   probe manifest records the latest `npm run lint` as exitCode 1", an entry
   the sibling branch (Companion) had written while Protoplast's files were
   mid-edit. The manifest is one file for every branch and carries no
   provenance.
7. **Two browser suites killed at 30 s** (33 s each, `run_shell` default),
   then re-run with `timeoutMs`.

In the delivered code, verified by reading `browser/control-connection.ts`
and `browser/control.ts`: the page polls every second and each `refresh()`
increments `refreshVersion`, so when every request takes more than a second
no refresh ever publishes and the page never shows a state (the previous
version handled that); the blocked-request test blocks only the first
request. Those stay for the follow-up run.

## Fixes (this commit)

1. `src/run/depth.ts`: once a pass wrote files, a later pass's text
   declaration is recorded, judged and persisted as files (`filesDelivered`);
   a pass that only ran a shell command keeps text open.
2. `src/tools/parentTests.ts`: a socket or FIFO in the tree, or an escaping
   link to one, is skipped and counted like the publication inventory does; a
   link to outside bytes still refuses. `src/atoms/resultGates.ts` and
   `src/core/parentTests.ts`: the no-result gate rejects only when both the
   task and one of its causes are new in the attempt (`onceKeys`: a copy
   cause by what it names, a runner cause by its suite), then reviews.
3. `src/atoms/fileEvidence.ts`: a number of three digits or more in the
   criteria (never a year, never the task description) is a criterion word.
   `src/atoms/verdict.ts`: a cut receipt keeps its request through the
   command and the rest of its tail; a `record_probe` receipt takes up to
   twice the first equal share.
4. Not shipped. A text call on a copy of the login, with the home's lease
   held only while copying, was built and withdrawn after the adversarial
   review: a revoked access token makes every concurrent copy refresh with the
   same single-use refresh token (a reuse that can revoke the login), a crash
   loses a rotation made in a copy, and the personal profile root's eight
   shared process seats then run out with a hard failure. Text calls stay
   serialized per home until a design holds the lease through the first
   response and keeps the crash guarantee.
5. Review texts: a plan with one implementation subtask has no join and needs
   no integration suite (`PARENT_TEST_BLOCKING_DEFECTS`, the review request);
   a suite asserts what the task states and nothing it leaves open
   (`PARENT_TEST_SUFFICIENCY`); an L1 plan is never refused for its parent's
   suite, and one naming a suite/task contradiction for the parent is
   acceptable (`VALIDATION_SYSTEM_PROMPT`, `PARENT_SUITE_CONTEXT_PREFIX`; the
   calibration reader still recognises the old prefix).
6. `src/atoms/groundTruth.ts`: a failing manifest entry whose latest
   `record_probe`, with that exit code, another branch recorded is named as
   that branch's observation, never this result's claim
   (`parallelBranchProbeLines`), decided from the attestation log.
7. `SHELL_TIMEOUT_MS` 30 s → 120 s (`run_shell` default), same host bound; a
   compiled script keeps 30 s before falling back to the model.
8. Numeric criteria: not built as a mechanism. `criteriaReview` now says a
   number a criterion states is met only by an assertion or observation that
   checks it, never by a test title or a passing total; the evidence fixes in
   3 are what the judge lacked. A measured timing gate would need its own
   design against the incidents collected so far.

Decisions 7 and 8 were taken here under the owner's standing delegation
(2026-10-16: no rule is fixed during the beta).

## Rollout

The adversarial review of these fixes also found the defects corrected above
(attribution of a branch's own failure to a sibling, a forced file delivery
after a shell-only pass, unrelated causes merged under one key, starved later
receipts, years read as criterion numbers, the old calibration prefix).

Fixes 2 and 7 execute inside the Compute worker image: a server deploy alone
does not reach the owner's Mac. The worker image is rebuilt and adopted as
[src/launcher](../../src/launcher/AGENTS.md) states (server first, then the
image pins with the desktop app that carries them). The follow-up run, from
`51c4e71d` as its base with a file delivery, repairs the slow-request
regression, the blocked-request detection and the cancellation paragraph.
